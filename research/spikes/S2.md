# S2: send contract on real Messages

Status: pass for 1:1 text and file sends. Group sends not tested.

Run on 2026-11-06 at 09:37 PST, macOS 26.2, through the S1 spike bridge (S1-BUILD-2). Every send went to the user's own Apple ID. The `rows` op prints metadata only for rows in that self-chat, and other rows print just their ROWID. Script: `spikes/s1/s2.sh`. Log: `spikes/s1/s2.log`.

Sends use an AppleScript handler called with `executeAppleEvent`, with handle and text passed as descriptors (no string interpolation):
`send t to participant h of (1st account whose service type = iMessage)`.

## Results

| Test | AppleScript result | Row | Outcome |
| --- | --- | --- | --- |
| Warm text | `sent`, 190 ms | New row within 1 s: from_me 1, text NULL, attributedBody 200 bytes containing the token | sent 1, delivered 1 at +2 s (delivered 0.5 s after the row date) |
| File staged in `/private/var/tmp/com.apple.messages/<app>/` | `sent`, 74 ms | New row with has_attachments 1, then `error = 25` | **Failed silently.** Attachment transfer_state 6. Messages removed the staged file. The message shows as not delivered |
| File staged in `~/Pictures/<app>/` | `sent`, 35 ms | New row with has_attachments 1 | sent 1, delivered 1 at +2 s. Attachment transfer_state 5. Messages copied the file into `~/Library/Messages/Attachments/` |
| Cold start (Messages quit first) | `sent`, 1,194 ms including the launch | New row within 1 s | sent 1, delivered 1 at +2 s |

Self-chat shape: each send made exactly one row, from_me 1, in the self chat. No echo copy appeared, from_me 0 or otherwise, in the 20 to 30 s windows or in a later check.

## What this changes in the design

1. **AppleScript success means nothing.** The tmp-staged file returned `sent` and then failed with error 25. The result must come from the row: `error`, `is_sent`, `is_delivered` and the attachment `transfer_state`. DESIGN section 3 already says this, and S2 shows it is required.
2. **Staging folder: `~/Pictures/<app>/`.** Messages copies the file into its own Attachments folder, so the bridge deletes the staged copy once transfer_state reaches 5, or after a timeout. `/private/var/tmp/com.apple.messages/` is ruled out.
3. **Correlation.** Text rows match on a body token in attributedBody, since text is NULL. File rows don't carry the token in the body, so they match on the attachment `transfer_name` (a unique staged file name) through `message_attachment_join`. The `chat_message_join` row can lag the message row by about 1 s, so correlation must allow for that.
4. **Timing.** Rows appear within 1 s and delivery within about 2 s. A cold start costs about 1 s extra, not the 60 s budget DESIGN allowed. Keep 60 s as the ceiling but expect about 3 s.
5. **Self-chat needs no echo dedupe** for sends made on this Mac. The fixture keeps its echo rows only as a defensive case.

## Not covered

- Group sends (needs consenting participants).
- SMS and RCS fallback.
- Sends while offline or to a handle not on iMessage (the `ghost` and `failed` paths).
- Files over a few KB, and images (HEIC conversion on the receiving side).
